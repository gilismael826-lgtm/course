## 详细笔记

### 一、RISC机器的特点

#### 1. RISC的诞生

**1981年**，第一台RISC（精简指令系统计算机）在美国**加州大学伯克利分校**问世。

**发展背景**：
- 继承了CISC的成功技术
- 克服了CISC机器的缺点

#### 2. RISC的三个基本要素 ⭐⭐⭐

```
┌─────────────────────────────────────────────────────────┐
│                    RISC三要素                            │
├─────────────────────────────────────────────────────────┤
│  ① 一个有限的简单的指令系统                              │
│  ② CPU配备大量的通用寄存器                               │
│  ③ 强调对指令流水线的优化                                │
└─────────────────────────────────────────────────────────┘
```

**RISC的目标**：
- 使处理器结构更简单、更合理
- 具有更高的性能和执行效率
- 降低处理器的开发成本

#### 3. RISC的主要特征

| 特征 | 说明 |
|-----|------|
| 指令长度 | 等长，典型4字节 |
| 寻址方式 | 少且简单，一般2-3种，最多不超过4种 |
| 访存指令 | 只有取数(LOAD)和存数(STORE)可以访问存储器 |
| 指令格式 | 一般少于4种 |
| 指令数目 | 一般少于100种 |
| 指令功能 | 简单，控制器多采用硬布线方式 |
| 执行时间 | 绝大多数指令在一个时钟周期内完成 |
| 寄存器数量 | 整数寄存器≥32个，浮点寄存器≥16个 |
| 控制器实现 | 硬布线控制为主 |
| 编译优化 | 强调编译器优化 |

⚠️ **绝不出现**：
- 存储器间接寻址方式
- SS型指令（存储器-存储器）

### 二、RISC与CISC的对比 ⭐⭐⭐

#### 📊 表5.5 CISC与RISC的主要特征对比

| 比较内容 | CISC | RISC |
|---------|------|------|
| **指令系统** | 复杂、庞大 | 简单、精简 |
| **指令数目** | 一般>200 | 一般<100 |
| **指令格式** | 一般>4 | 一般<4 |
| **寻址方式** | 一般>4 | 一般<4 |
| **指令字长** | 不固定 | 等长 |
| **可访存指令** | 不加限制 | 只有LOAD/STORE |
| **指令使用频率** | 相差很大 | 相差不大 |
| **指令执行时间** | 相差很大 | 绝大多数一个周期完成 |
| **优化编译** | 很难 | 较容易 |
| **源代码长度** | 较短 | 较长 |
| **控制器实现** | 绝大多数微程序控制 | 绝大多数硬布线控制 |
| **软件开发时间** | 较短 | 较长 |

#### 核心差异总结

```
CISC：用硬件复杂度换取软件简单性
      ↓
   指令功能强大 → 指令条数少 → 程序短
      ↓
   但控制器复杂、执行时间不均衡

RISC：用软件复杂度换取硬件简单性
      ↓
   指令功能简单 → 指令条数多 → 程序长
      ↓
   但控制器简单、执行快速、适合流水线
```

#### 2. TaiShan V110处理器内核

#### 📷 图5.44 TaiShan V110处理器内核的顶层功能方框图

![图5.44 TaiShan V110处理器内核](../../images/caac919d4865c2852edbb2a3951988d00ce26d348a92f19287409f9e82b24148.jpg)

> 📚 **课本出处**：图5.44 TaiShan V110内核集成处理器及私有L2 cache，支持超标量和乱序执行

**内核组成部件**：

| 部件 | 功能 |
|-----|------|
| **取指部件** | 从L1 I-cache取指令，每周期最多4条；支持动态/静态分支预测 |
| **指令译码部件** | A64指令集译码，寄存器重命名，消除WAW和WAR冒险 |
| **指令分发部件** | 控制指令分发至执行单元，包含通用寄存器文件等 |
| **整数执行部件** | 3条ALU流水线+1条MDU流水线，支持乘加运算 |
| **加载/存储单元** | 执行LOAD/STORE指令，管理L1 D-cache |
| **L2存储系统** | 512KB L2 cache，8路组相联 |
| **浮点/SIMD单元** | 支持ARMv8-A增强SIMD与浮点运算 |
| **通用中断控制器** | 向处理器发送中断请求 |
| **通用定时器** | 事件调度支持 |
| **性能监视器PMU** | 系统性能调优支持 |
| **调试与跟踪部件** | 支持ARMv8调试架构 |

#### 3. 鲲鹏流水线技术

#### 📷 图5.45 鲲鹏处理器指令流水线结构

![图5.45 鲲鹏处理器指令流水线结构](../../images/ff82339d9c4d2da38ac50158ec7eab0d74fa993d391731050588d3d7cc2d59f3.jpg)

> 📚 **课本出处**：图5.45 鲲鹏920采用八级指令流水线结构

**八级流水线**：

| 级数 | 名称 | 功能 |
|-----|------|------|
| 1 | 取指 | 从I-cache取指令，计算下条指令地址，分支预测 |
| 2 | 译码 | 识别指令类型，确认操作数地址 |
| 3 | 分配/寄存器重命名 | 逻辑寄存器重命名为物理寄存器，解决WAW和WAR相关 |
| 4 | 分发 | 指令派发到不同运算单元的等待队列 |
| 5 | 发射 | 指令无序发射到运算单元，开始乱序执行 |
| 6 | 运算(执行) | 在8个执行单元中执行运算 |
| 7 | 写回 | 结果写入物理寄存器 |
| 8 | 提交 | 恢复指令顺序，确定推测执行结果，输出最终结果 |

**8个执行单元**：

| 执行单元 | 功能 |
|---------|------|
| ALU1 | 整型运算 |
| ALU2/BRU1 | 整型运算、分支跳转 |
| ALU3/BRU2 | 整型运算、分支跳转 |
| MDU | 整型移位、乘法、除法、CRC运算 |
| Load/Store 0 | 加载/存储操作 |
| Load/Store 1 | 加载/存储操作 |
| FP/ASIMD 1 | 浮点运算与增强SIMD运算 |
| FP/ASIMD 2 | 浮点运算与增强SIMD运算 |

**关键技术**：
- ✅ **超标量**：一个周期内发射多条指令
- ✅ **乱序执行**：指令按数据准备情况执行，不按程序顺序
- ✅ **寄存器重命名**：消除WAW和WAR相关
- ✅ **推测执行**：预测分支方向，提前执行指令
- ✅ **动态调度**：硬件动态调整指令执行顺序

## 核心考点总结

### ⭐⭐⭐ 必考内容

1. **RISC的三个基本要素**
   - 有限的简单指令系统
   - 大量通用寄存器
   - 强调指令流水线优化

2. **RISC的主要特征**（与CISC对比）

| 特征 | RISC特点 |
|-----|---------|
| 指令长度 | 等长 |
| 寻址方式 | 少且简单 |
| 访存指令 | 只有LOAD/STORE |
| 控制器 | 硬布线为主 |
| 执行时间 | 绝大多数一个周期 |

3. **RISC与CISC的核心差异**

```
CISC：复杂指令 → 微程序控制 → 执行时间不均衡
RISC：简单指令 → 硬布线控制 → 执行快速规整
```

4. **鲲鹏920处理器特点**

| 特性 | 参数 |
|-----|------|
| 架构 | ARMv8-A兼容 |
| 内核 | TaiShan V110 |
| 最大核数 | 64核 |
| 流水线 | 8级 |
| 执行方式 | 超标量、乱序执行 |
| 每周期发射 | 最多4条指令 |
| L2 cache | 每核512KB |

### 📌 易混淆点辨析

| 概念 | 说明 |
|-----|------|
| **RISC** | 精简指令集计算机，指令简单、硬布线控制 |
| **CISC** | 复杂指令集计算机，指令复杂、微程序控制 |
| **超标量** | 每周期可发射多条指令 |
| **超流水线** | 流水线级数很多，时钟周期短 |
| **乱序执行** | 指令按数据准备情况执行，不按程序顺序 |
| **寄存器重命名** | 用物理寄存器消除WAW和WAR相关 |
