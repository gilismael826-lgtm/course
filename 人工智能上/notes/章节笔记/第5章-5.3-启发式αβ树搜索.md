## 一、核心思想

### 1.1 为什么需要启发式搜索？

**问题**：即使使用α-β剪枝，博弈树仍然太大，无法搜索到终止状态

**解决方案**：
- **提前截断搜索**（Cutoff）
- 使用**启发式评价函数**（EVAL）估计状态效用值
- 将非终止节点"转变"为终止节点

### 1.2 启发式极小化极大值（H-MINIMAX）

```
H-MINIMAX(s, d) =
  EVAL(s, MAX)                              如果 Is-CUTOFF(s, d)
  max{ H-MINIMAX(RESULT(s,a), d+1) }         如果 TO-MOVE(s) = MAX
  min{ H-MINIMAX(RESULT(s,a), d+1) }         如果 TO-MOVE(s) = MIN
```

**关键组件**：
- `EVAL(s, p)`：评价函数，估计状态s对玩家p的效用值
- `Is-CUTOFF(s, d)`：截断测试，决定是否停止搜索

## 二、5.3.1 评价函数 ⭐⭐⭐

### 2.1 评价函数的要求

1. **计算速度快**（重点是加快搜索速度）
2. **与实际获胜机会密切相关**
3. **终止状态**：EVAL(s, p) = UTILITY(s, p)
4. **非终止状态**：UTILITY(loss, p) ≤ EVAL(s, p) ≤ UTILITY(win, p)

### 2.2 评价函数的构建方法

#### 方法一：期望值法（理论）

假设某类别状态（如"两兵对一兵"）：
- 82% 通向胜利（效用值+1）
- 2% 导致失败（效用值0）
- 16% 为平局（效用值1/2）

期望值 = 0.82×1 + 0.02×0 + 0.16×0.5 = **0.90**

#### 方法二：加权线性函数（实际常用）

$$
\text{EVAL}(s) = w_1 f_1(s) + w_2 f_2(s) + \dots + w_n f_n(s) = \sum_{i=1}^{n} w_i f_i(s)
$$

**国际象棋示例**：

| 特征 | 权重 |
|------|------|
| 白兵数目 | +1 |
| 黑马数目 | -3 |
| 白后数目 | +9 |
| 黑车数目 | -5 |
| 好的兵阵 | +0.5 |
| 王的安全 | +0.5 |

**图5-8示例**：

```
局面(a)：黑方有马+两兵优势 → 黑方胜势
局面(b)：白方下一步吃后 → 白方胜势
```

### 2.3 非线性组合

**问题**：线性假设太强（特征贡献独立）

**改进**：
- 一对象 > 2×单个象（协同效应）
- 残局中象价值更高（与剩余棋子数相关）

### 2.4 权重获取

1. **人类经验**（传统方法）
2. **机器学习**（现代方法）：几小时学习可复制几个世纪的人类经验

## 三、5.3.2 截断搜索 ⭐⭐⭐

### 3.1 基本实现

```python
def IS-CUTOFF(state, depth):
    # 终止状态必须截断
    if IS-TERMINAL(state):
        return True
    # 达到深度限制
    if depth >= max_depth:
        return True
    return False
```

### 3.2 迭代加深

```mermaid
flowchart LR
    A[深度=1] --> B[搜索并记录最佳移动]
    B --> C[深度=2]
    C --> D[利用之前排序]
    D --> E[深度=3]
    E --> F[...]
    
    style A fill:#ff9999
    style C fill:#ffcc99
    style E fill:#90EE90
```

**优势**：
- 时间耗尽时返回最深已完成搜索的结果
- 维护换位表加速后续轮次
- 用评估值改进移动顺序

### 3.3 静态搜索（Quiescence Search）⭐

**问题**：在图5-8b的局面截断，会误判局势

**现象**：评价函数只能应用于**静态局面**（不存在使评估值大幅摇摆的待定移动）

**解决方案**：

```python
def IS-CUTOFF(state, depth):
    if IS-TERMINAL(state):
        return True
    if depth >= max_depth:
        # 检查是否为静态局面
        if is_quiescent(state):
            return True
        else:
            # 继续搜索（静态搜索）
            return False
    return False
```

**静态搜索特点**：
- 只考虑特定类型移动（如吃子）
- 快速消除不确定性
- 通常限制搜索范围

### 3.4 视野效应（Horizon Effect）⭐⭐

#### 问题描述

**图5-9示例**：
- 黑象注定被吃（白车h2→h1→a1→吃象）
- 但黑方可以用兵阻挡，将损失推到"视野"之外
- 程序误以为这是"好招"

```mermaid
graph TD
    A[当前局面<br/>黑象将被吃] --> B[兵阻挡王]
    B --> C[王吃兵]
    C --> D[兵再阻挡]
    D --> E[王再吃兵]
    E --> F[搜索深度耗尽<br/>象暂时"安全"]
    
    style A fill:#ff9999
    style F fill:#ffcc99
```

#### 解决方案：单步延伸（Singular Extension）

**思想**：如果有明显更好的移动，允许延伸搜索

**实现**：

```python
def search(state, depth, alpha, beta):
    if IS-TERMINAL(state):
        return UTILITY(state)
    
    # 检查是否为单步延伸情况
    if depth <= 0 and not is_singular_move(state):
        return EVAL(state)
    
    # 正常搜索...
```

**效果**：
- 白车的3次移动依次都是"明显更好"
- 即使兵的序列推到视野外，这些移动会被延伸搜索
- 不会增加太多节点，但有效解决视野效应

## 四、5.3.3 前向剪枝（Forward Pruning）⭐⭐

### 4.1 核心思想

**α-β剪枝**：剪掉对结果**没有影响**的分支（安全）

**前向剪枝**：剪掉**看上去糟糕**但可能实际很好的移动（有风险）

> 香农的B型策略：舍弃看起来差的移动

### 4.2 束搜索（Beam Search）

**方法**：每层只考虑n个最佳移动（根据评价函数）

**风险**：无法保证最佳移动不被剪枝

### 4.3 PROBcut（概率截断）⭐

**思想**：利用统计信息减少剪除最佳移动的概率

**原理**：
- α-β剪枝：剪掉**可证明**在(α, β)窗口外的节点
- PROBcut：剪掉**有可能**在窗口外的节点

**步骤**：
1. 执行浅层搜索计算倒推值v
2. 利用历史经验估计v位于(α, β)外的概率
3. 概率高则剪枝

**效果**：LOGISTELLO程序以64%胜率击败常规版本（即使后者有2倍时间）

### 4.4 后期移动缩减（Late Move Reduction）

**假设**：移动顺序已调整好，列表后期的移动不太可能是好的

**方法**：
- 不完全删除后期移动
- 减少搜索深度（而非完全剪枝）
- 如果缩减搜索返回值高于α，重新全深度搜索

### 4.5 国际象棋程序性能对比

| 技术 | 搜索深度 | 水平 |
|------|---------|------|
| 纯Minimax（1分钟） | 5层 | 被普通棋手击败 |
| α-β + 换位表 | 14层 | 专家级 |
| 8 GPU工作站 | 更深 | 大师级 |
| STOCKFISH（全功能） | 30+层 | 超越人类 |

## 五、5.3.4 搜索与查表 ⭐

### 5.1 开局库（Opening Book）

**问题**：开局搜索10亿状态，结论只是"兵e4"

**解决方案**：使用人类专家知识
- 从书籍复制最佳开局建议
- 从数据库收集统计数据
- 前10-15步查表，之后切换搜索

### 5.2 残局库（Endgame Tablebase）

**优势**：
- 计算机分析远超人类
- 可能局面少，可完全求解

**构建方法**：逆向极小化极大搜索
1. 考虑所有可能终局配置
2. 标记必胜/必败/平局局面
3. 逆向推导，标记所有局面
4. 构建查询表

**规模**：
- 7子残局：400万亿状态（已解决）
- 8子残局：40000万亿状态

## 六、关键要点总结

### 6.1 核心概念对比

| 概念 | 目的 | 方法 | 风险 |
|------|------|------|------|
| **截断搜索** | 解决树太大 | 深度限制+EVAL | 评估误差 |
| **静态搜索** | 解决截断误差 | 非静态局面继续搜 | 额外计算 |
| **单步延伸** | 解决视野效应 | 明显好移动延伸 | 树增大 |
| **前向剪枝** | 进一步减少搜索 | 剪掉看似差的移动 | 可能剪错 |
| **查表** | 避免重复计算 | 开局/残局库 | 存储需求 |

### 6.2 评价函数设计要点

1. **特征选择**：与获胜机会相关的可计算特征
2. **权重确定**：人类经验或机器学习
3. **线性vs非线性**：根据特征相关性选择
4. **计算效率**：必须快速计算
