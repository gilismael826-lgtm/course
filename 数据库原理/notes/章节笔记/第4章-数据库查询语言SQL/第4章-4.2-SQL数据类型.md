## 详细笔记

### 一、字符串型（4.2.1）

> 📚 **课本出处**：第4章 4.2.1节"字符串型"

在SQL Server 2017中，字符串型数据可以由汉字、英文字母、数字等符号组成。根据编码方式的不同，分为**Unicode字符串型**和**非Unicode字符串型**。

- **Unicode字符串型**：对所有字符均采用双字节（16位）统一编码
- **非Unicode字符串型**：不同国家/地区采用不同编码长度（英文字母1字节/8位，汉字2字节/16位）

#### 表4.2 字符串型数据类型

| 数据类型 | 编码方式 | 长度 | 说明 |
|:-------:|:--------:|:----:|:-----|
| char(n) | 非Unicode | 固定 | n取值1~8000，存储固定长度字符串 |
| varchar(n) | 非Unicode | 可变 | n取值1~8000，存储可变长度字符串 |
| text | 非Unicode | 可变 | 最大容量约2GB（2^31-1字节） |
| nchar(n) | Unicode | 固定 | n取值1~4000，占用2n字节存储空间 |
| nvarchar(n) | Unicode | 可变 | n取值1~8000 |
| ntext | Unicode | 可变 | 最大容量约2GB（2^31-1字节） |

> 💡 **理解技巧**：char与varchar的区别——char即使数据不满也会用空格补齐到n长度（固定），varchar则按实际长度存储（变长）。需要存储中文等多字节字符时应选择nchar/nvarchar系列。

> ⚠️ **常见误区**：char(n)中的n表示字符数而非字节数。nchar(n)虽然n也是字符数，但由于每个字符占2字节，实际存储空间为2n字节。

### 二、数值型（4.2.2）

> 📚 **课本出处**：第4章 4.2.2节"数值型"

按照不同的精确程度，可以将数值型数据类型分为**精确型**和**近似型**。

#### 1. 精确型

精确型数据是指在计算机中可以**精确存储**的数据，包括各种整型和定点型。

##### 表4.3 精确型数据类型

| 数据类型 | 字节 | 存储范围 | 说明 |
|:-------:|:----:|:--------|:-----|
| bit | 1 | 0或1 | 位整型，也可取NULL |
| tinyint | 1 | 0~255 | 小整型 |
| smallint | 2 | -32768 ~ 32767 | 短整型，即 $-2^{15}$ ~ $2^{15}-1$ |
| int (integer) | 4 | -2147483648 ~ 2147483647 | 整型，即 $-2^{31}$ ~ $2^{31}-1$ |
| bigint | 8 | -9223372036854775808 ~ 9223372036854775807 | 大整型，即 $-2^{63}$ ~ $2^{63}-1$ |
| numeric(m,n) | 最多17 | $-10^{38}+1$ ~ $10^{38}-1$ | 定点型，m为总有效位数，n为小数位数 |
| decimal(m,n) | 最多17 | 同numeric | 功能同numeric(m,n) |

> 💡 **理解技巧**：numeric(m,n)中，m是小数点两边的十进制位数之和，n是小数点右边的位数。例如numeric(8,2)可存储最大值999999.99。n默认值为0，且 $0 \leq n \leq m$。

#### 2. 近似型

近似型主要是指浮点型，数据在内存中不一定能够精确表示，可能存在微小误差。

##### 表4.4 近似型数据类型（real 和 float）

| 数据类型 | 字节 | 存储范围 | 精度 |
|:-------:|:----:|:--------|:-----|
| real | 4 | -3.40E+38 ~ 3.40E+38 | 精确到小数点后7位 |
| float | 8 | -1.79E+308 ~ 1.79E+308 | 近似数值类型 |

> ⚠️ **常见误区**：近似型数据不适合用于需要精确计算的场景（如金融计算），应使用精确型如numeric(m,n)或货币型。

### 三、日期时间型（4.2.3）

> 📚 **课本出处**：第4章 4.2.3节"日期时间型"

早期SQL Server版本中，日期型和时间型合称为日期时间型（datetime和smalldatetime）。从SQL Server 2012开始，新增了4种类型，使日期时间表示更为灵活。

#### 表4.5 日期时间型数据类型

| 数据类型 | 字节 | 存储内容 | 范围 | 精度 |
|:-------:|:----:|:--------|:-----|:-----|
| date | 3 | 仅日期 | 1年~9999年12月31日 | 天 |
| time(n) | 3~5 | 仅时间 | 00:00:00.0000000~23:59:59.9999999 | 100纳秒 |
| smalldatetime | 4 | 日期+时间 | 1900-1-1~2079-6-6 | 分钟 |
| datetime | 8 | 日期+时间 | 1753-1-1~9999-12-31 | 3.33毫秒 |
| datetime2(n) | 6~8 | 日期+时间 | 1年~9999年12月31日 | 100纳秒 |
| datetimeoffset(n) | 8~10 | 日期+时间+时区 | 1年~9999年12月31日 | 100纳秒 |

> 💡 **理解技巧**：time(n)中n取值0~7，指定秒的小数位数。datetimeoffset带有时区偏移量（最大+/-14小时），适合跨时区应用。

---

### 四、货币型（4.2.4）

> 📚 **课本出处**：第4章 4.2.4节"货币型"

货币型用来存储货币值数据，固定精确到**小数点后四位**，相当于numeric(m,n)类型的特例（n=4）。

#### 表4.6 货币型数据类型

| 数据类型 | 字节 | 存储范围 | 精度 |
|:-------:|:----:|:---------|:-----|
| smallmoney | 4 | -214748.3648 ~ +214748.3647 | 精确到货币单位的千分之十 |
| money | 8 | -922337203685477.5808 ~ +922337203685477.5807 | 精确到货币单位的千分之十 |

---

### 五、二进制型（4.2.5）

> 📚 **课本出处**：第4章 4.2.5节"二进制型"

二进制型数据类型包括三种：binary(n)、varbinary(n)和image。

#### 表4.7 二进制型数据类型

| 数据类型 | 长度 | 说明 |
|:-------:|:----:|:-----|
| binary(n) | 固定 | n取值1~8000字节，固定长度二进制数据 |
| varbinary(n) | 可变 | n取值1~8000字节，可变长度二进制数据 |
| image | 可变 | 最大约2GB（2^31-1字节），可存储文本、GIF等多种格式文件 |

> 💡 **理解技巧**：binary和varbinary的关系类似于char和varchar——binary固定长度，varbinary可变长度。image适合存储图片、文档等大对象。

---

### 六、其他数据类型（4.2.6）

> 📚 **课本出处**：第4章 4.2.6节"其他数据类型"

| 数据类型 | 说明 |
|:-------:|:-----|
| sql_variant | 通用数据类型，可存储除text、ntext、image、timestamp及自身以外的其他类型，最大8000字节 |
| timestamp | 时间戳类型，每次更新时自动更新，用于证明操作在某一时刻完成 |
| uniqueidentifier | 全局唯一标识符（GUID），可通过Newsequentialid()函数获得，值在所有计算机上唯一 |
| xml | XML存储格式，支持添加/删除子树和更新标量值，最多2GB |
| table | 表类型，用于返回表值函数的结果集，大小取决于列数和行数 |
| hierarchyid | 层次类型，包含层次结构中位置的引用，1~892字节+2字节额外开销 |
| cursor | 游标类型，仅能用作变量或存储过程参数，不能用于CREATE TABLE语句 |

---

### 七、自定义数据类型（4.2.7）

> 📚 **课本出处**：第4章 4.2.7节"自定义数据类型"

用户可利用已有的标准数据类型来定义自己的数据类型，称为**自定义数据类型**。

**创建自定义数据类型**：

```sql
-- 创建表示地址的数据类型 address
CREATE TYPE address FROM varchar(350) NOT NULL;
```

- 执行后生成名为address的数据类型，等效于varchar(350)，但增加了NOT NULL约束
- 此后可以用address去定义字段和变量

**删除自定义数据类型**：

```sql
-- 删除自定义数据类型 address
DROP TYPE address;
```

> ⚠️ **常见误区**：删除自定义数据类型之前，必须先删除所有引用该数据类型的数据库对象，否则删除操作会失败。

## 总结

### SQL数据类型分类速查表

| 类别 | 数据类型 | 适用场景 | 关键特征 |
|:----:|:---------|:---------|:---------|
| **字符串型** | char(n), varchar(n) | 英文/数字文本 | 非Unicode，定长/变长 |
| | nchar(n), nvarchar(n) | 含中文文本 | Unicode，定长/变长 |
| | text, ntext | 大文本 | 最大约2GB |
| **精确数值型** | bit | 布尔值 | 仅0或1 |
| | tinyint, smallint, int, bigint | 整数 | 范围递增 |
| | numeric(m,n), decimal(m,n) | 精确小数 | 可设定精度和小数位 |
| **近似数值型** | real, float | 浮点数 | 有微小误差 |
| **日期时间型** | date | 仅日期 | 3字节 |
| | time(n) | 仅时间 | 精确到100纳秒 |
| | datetime, datetime2 | 日期+时间 | datetime2精度更高 |
| | datetimeoffset | 日期+时间+时区 | 跨时区应用 |
| **货币型** | smallmoney, money | 货币计算 | 固定4位小数 |
| **二进制型** | binary(n), varbinary(n) | 二进制数据 | 定长/变长 |
| | image | 图片/大对象 | 最大约2GB |
| **其他** | sql_variant, timestamp, uniqueidentifier, xml, table, hierarchyid, cursor | 特殊用途 | 各有专用场景 |
| **自定义** | CREATE TYPE定义 | 用户需求 | 基于已有类型扩展 |

### 关键要点

1. **Unicode vs 非Unicode**：含中文内容优先选择nchar/nvarchar，纯英文可选char/varchar以节省空间
2. **定长 vs 变长**：char/varchar、binary/varbinary的区别与char/nchar同理
3. **精确型 vs 近似型**：金融等精确计算用numeric/decimal，科学计算可用real/float
4. **日期时间型选择**：只需日期用date，只需时间用time，需时区用datetimeoffset
5. **自定义类型**：基于标准类型创建，可附加约束条件，使用前需确保无引用才能删除
6. **currency特例**：货币型本质上是n=4的numeric(m,n)

## 疑问与思考

❓ **疑问**：varchar 和 nvarchar 存中文有什么区别？

💡 **解答**：
- **varchar**：非 Unicode，1个中文占 **2 字节**，varchar(100) 最多存 50 个汉字
- **nvarchar**：Unicode，1个中文占 **2 字节但更规范**，nvarchar(100) 最多存 100 个汉字
- 存中文推荐用 **nvarchar**，避免编码问题

❓ **疑问**：numeric(m,n) 的 m 和 n 分别是什么意思？

💡 **解答**：
- **m** = 总位数（整数部分 + 小数部分），**n** = 小数位数
- 例：numeric(8,2) → 整数部分 6 位 + 小数 2 位，最大值 999999.99
- 占用字节数取决于 m 的大小，m 越大字节越多

❓ **疑问**：char 和 varchar 的选择原则是什么？

💡 **解答**：
- **char(n)**：定长，适合长度固定的数据（如身份证号、手机号），存取快但可能浪费空间
- **varchar(n)**：变长，适合长度变化大的数据（如姓名、地址），节省空间但需额外记录长度

### 💡 个人理解/技巧
- 记忆数据类型的核心思路：**字符用char系，数字用int/numeric系，时间用date/time系，钱用money系，二进制用binary系**
- char(n)存储英文比varchar快（定长可直接定位），但浪费空间；varchar节省空间但需要额外记录长度
- numeric(8,2)可以理解为"总共8位数字，其中2位是小数"，最大值为999999.99
- datetime2比datetime更精确（100纳秒 vs 3.33毫秒），且范围更大（从1年开始 vs 从1753年开始），推荐新项目使用datetime2
- image类型在SQL Server后续版本中已被标记为弃用，推荐使用varbinary(max)替代
