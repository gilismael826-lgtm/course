## 重点内容

### ⭐⭐⭐ 核心语法
- **删除数据库**：`DROP DATABASE { database_name | database_snapshot_name } [,...n]`
- 支持同时删除多个数据库
- 删除前**必须备份**

### ⭐⭐ 关键区别
- **DROP DATABASE**：删除数据库并同时删除磁盘上的数据文件和日志文件，**数据不可恢复**
- **分离（sp_detach_db）**：仅将数据库从服务器分离，文件保留在磁盘上
- **DELETE**：是DML语句，用于删除表中的数据行，不是删除数据库

### ⭐ 重要警告
- 删除操作不可逆，一旦执行，数据库中的数据**永久丢失**
- 在实际应用中，不管删除哪个数据库，删除之前都应进行备份
- 不能删除系统数据库（master、model、tempdb、msdb）

---

## 详细笔记

### 一、DROP DATABASE 语法

> 📚 **课本出处**：第6章 6.6节"删除数据库"

当数据库已经确认不再需要时，应该将之删除，以释放服务器资源。

> ⚠️ **重要警告**：为了避免不必要的损失，在实际应用当中不管删除哪一个数据库，在删除之前都应进行**备份**。

```sql
DROP DATABASE { database_name | database_snapshot_name } [,...n] [;]
```

**参数说明**：

| 参数 | 说明 |
|:-----|:-----|
| `database_name` | 要删除的数据库名称 |
| `database_snapshot_name` | 要删除的数据库快照名称 |

> 💡 **理解技巧**：`DROP DATABASE` 支持在一条语句中同时删除多个数据库，只需用逗号分隔即可。这在批量清理测试数据库时非常方便。

---

### 二、删除单个数据库

**【例6.14】删除单个数据库**

删除数据库 `MyDatabase`：

```sql
USE master;
GO
DROP DATABASE MyDatabase;
```

> ⚠️ **注意**：删除数据库前通常需要先 `USE master` 切换到 master 数据库，因为不能删除当前正在使用的数据库。

---

### 三、同时删除多个数据库

**【例6.15】同时删除多个数据库**

删除数据库 `MyDatabase2`、`MyDatabase3`、`MyDatabase4`：

```sql
USE master;
GO
DROP DATABASE MyDatabase2, MyDatabase3, MyDatabase4;
```

---

### 四、删除的后果

> 📚 **课本出处**：第6章 6.6节（删除数据库后的注意事项）

使用 `DROP DATABASE` 语句删除数据库以后，**数据文件和日志文件都将从磁盘上删除**。一旦使用了 `DROP DATABASE` 语句，数据库中的数据是**不可恢复的**。

| 操作 | 数据库文件 | 数据是否可恢复 |
|:-----|:---------:|:------------:|
| DROP DATABASE | 从磁盘删除 | **不可恢复** |
| 分离数据库（sp_detach_db） | 保留在磁盘上 | **可恢复**（重新附加即可） |

> 📌 **考试重点**：如果只是希望将数据库从当前服务器中删除，但不希望从文件系统删除数据库文件，则应使用**数据库分离**的方法，而不是 `DROP DATABASE`。

## 总结

### 第6章 数据库操作全景对比

| 操作 | 语法 | 数据文件 | 数据可恢复 | 用途 |
|:-----|:-----|:-------:|:---------:|:-----|
| 查看数据库 | `sp_helpdb` / `SELECT FROM sysdatabases` | 不影响 | - | 获取数据库信息 |
| 修改数据库名 | `ALTER DATABASE ... MODIFY NAME` | 不影响 | - | 更名操作 |
| 修改数据库大小 | `ALTER DATABASE ... MODIFY FILE` | 属性变更 | - | 扩容/调整 |
| 分离数据库 | `sp_detach_db` | 保留 | 可恢复 | 迁移、备份 |
| 附加数据库 | `CREATE DATABASE ... FOR ATTACH` | 利用已有文件 | - | 恢复分离的数据库 |
| **删除数据库** | `DROP DATABASE` | **删除** | **不可恢复** | 彻底清理 |

### 关键要点

1. `DROP DATABASE` 语法简单但后果严重——数据文件和日志文件都被删除且不可恢复
2. 删除前**必须备份**，这是数据库管理的基本原则
3. 可以在一条语句中同时删除多个数据库
4. 删除数据库前需要先切换到 `master` 数据库
5. 如果只是不想让数据库出现在服务器中但保留数据文件，应该用**分离**而不是**删除**
6. 系统数据库（master、model、tempdb、msdb）不能被随意删除

## 疑问与思考

### ❓ 待解决问题
1. **DROP 与 DELETE 的区别是什么？**
   - `DROP DATABASE` 是 DDL 语句，删除整个数据库（包括文件和数据）
   - `DELETE` 是 DML 语句，只删除表中的数据行，不删除表结构，更不删除数据库
   - 类似地，`DROP TABLE` 删除整张表，而 `DELETE FROM table` 只删除表中的数据

2. **删除系统数据库会怎样？**
   - `master` 数据库存储所有系统信息，删除后 SQL Server 无法启动
   - `model` 是创建新数据库的模板，删除后无法创建新数据库
   - `tempdb` 存储临时数据，删除后会自动重建（但当前会话会中断）
   - `msdb` 存储代理调度信息，删除后备份和作业调度会失效
   - 一般情况下**不应删除任何系统数据库**

3. **分离 vs 删除的区别是什么？**
   - **分离**：数据库从服务器脱离，但 .mdf 和 .ldf 文件保留在磁盘上，可通过附加恢复
   - **删除**：数据库从服务器脱离，同时 .mdf 和 .ldf 文件从磁盘上删除，数据不可恢复
   - 选择原则：想保留数据用分离，想彻底清除用删除

### 💡 个人理解/技巧
- `DROP DATABASE` 操作相当于"格式化+删除"，比物理删除文件更彻底（还会清除系统目录中的记录）
- 生产环境中永远不要手动执行 `DROP DATABASE`，应通过备份策略和自动化工具管理
- 测试环境中创建的临时数据库，用完后应立即 `DROP` 释放资源，避免遗忘
- 三者的危险程度排序：`DELETE FROM table` < `DROP TABLE` < `DROP DATABASE`
- 如果误删了数据库，只能通过之前的备份来恢复——所以备份是最后的保险
