## 重点内容

### ⭐⭐⭐ 核心概念
- **CREATE DATABASE语句**：创建数据库的核心SQL语法，包含ON、LOG ON、COLLATE等子句
- **filespec定义**：NAME、FILENAME、SIZE、MAXSIZE、FILEGROWTH五大参数
- **文件初始大小**：数据文件默认3MB，日志文件默认1MB
- **主文件与次要文件的区分**：由定义顺序决定，而非扩展名

### ⭐⭐ 重要概念
- **默认参数创建**：最简单的CREATE DATABASE形式，仅指定数据库名
- **LOG ON子句**：指定日志文件，若不指定则自动创建（大小为数据文件总和的25%或512KB取较大值）
- **FILEGROUP子句**：定义用户文件组，可使用DEFAULT关键字设为默认文件组

### ⭐ 基础概念
- **UNLIMITED**：表示文件无限增长，实际受磁盘空间限制
- **FILEGROWTH**：可使用百分比或绝对数值，设为0则关闭自动增长

## 详细笔记

### 一、CREATE DATABASE语法（6.2.1）

> 📚 **课本出处**：第6章 6.2.1节"创建数据库的SQL语法"

#### 完整语法

```sql
CREATE DATABASE database_name
[ON
    [PRIMARY] [<filespec> [,...n]]
    [, <filegroup> [,...n]]
[LOG ON [<filespec> [,...n]]]
]
[COLLATE collation_name]
[WITH <external_access_option>];
```

其中，`<filespec>`、`<filegroup>` 和 `<external_access_option>` 的定义如下：

```sql
<filespec> ::=
{
    NAME = logical_file_name,
    FILENAME = 'os_file_name'
    [, SIZE = size [KB|MB|GB|TB]]
    [, MAXSIZE = {max_size [KB|MB|GB|TB] | UNLIMITED}]
    [, FILEGROWTH = growth_increment [KB|MB|GB|TB|%]]
} [,...n]

<filegroup> ::=
{
    FILEGROUP filegroup_name [CONTAINS FILESTREAM] [DEFAULT]
    <filespec>[,...n]
}

<external_access_option> ::=
{
    [DB_CHAINING {ON|OFF}]
    [, TRUSTWORTHY {ON|OFF}]
}
```

> 📚 **课本出处**：第6章 6.2.1节 CREATE DATABASE完整语法定义

#### 语法参数详解

| 参数 | 说明 | 默认值/约束 |
|:----:|:-----|:----------:|
| **database_name** | 数据库名称，当前实例中必须唯一，符合标识符规则 | 最大128字节 |
| **ON** | 指定数据文件，后跟逗号分隔的`<filespec>`列表 | 可选 |
| **PRIMARY** | 指定关联的`<filespec>`列表定义主文件 | 未指定时database_name成为主文件 |
| **NAME** | 数据库文件的逻辑名称 | 未指定则使用database_name |
| **FILENAME** | 数据库文件的物理文件名（操作系统文件名） | 未指定则在NAME后加.mdf/.ldf |
| **SIZE** | 数据库文件的初始大小 | 数据文件3MB，日志文件1MB |
| **MAXSIZE** | 文件能够增长到的最大值 | UNLIMITED：日志文件2TB，数据文件16TB |
| **FILEGROWTH** | 文件大小增长幅度，可用百分比或绝对数值 | 0表示关闭自动增长 |
| **LOG ON** | 指定存储数据库日志的磁盘文件 | 自动创建：数据文件总和的25%或512KB取大值 |
| **FILEGROUP** | 定义文件组 | 名称在数据库中唯一，不能是PRIMARY/PRIMARY_LOG |
| **COLLATE** | 指定数据库的默认排序规则 | SQL Server实例的默认排序规则 |

> 📚 **课本出处**：第6章 6.2.1节 CREATE DATABASE语法参数说明

### 二、创建使用默认参数的数据库（6.2.2）

> 📚 **课本出处**：第6章 6.2.2节"创建使用默认参数的数据库"

这是最简单、也是较为常用的数据库创建方法，所有参数使用默认设置：

```sql
CREATE DATABASE database_name;
```

#### 例6.1 创建名为DB1的数据库（所有参数使用默认值）

```sql
CREATE DATABASE DB1;
```

执行结果：自动生成以下文件
- 数据文件：DB1.mdf（逻辑名：DB1，初始大小：3MB）
- 日志文件：DB1_log.ldf（逻辑名：DB1_log，初始大小：1MB）

> 💡 **理解技巧**：这是日常开发中最常用的创建方式，简单快捷。适合快速建立测试数据库。

---

### 三、创建指定数据文件的数据库（6.2.3）

> 📚 **课本出处**：第6章 6.2.3节"创建指定数据文件的数据库"

当需要指定数据文件名和日志文件名时，需要在CREATE DATABASE语句中指定NAME和FILENAME的值。

#### 例6.2 创建指定数据文件逻辑名和物理名的数据库

```sql
CREATE DATABASE DB2
ON PRIMARY
(
    NAME = 'LogicFile2',
    FILENAME = 'D:\datafiles\DataFile2.mdf'
);
```

> 📚 **课本出处**：第6章 6.2.2节 例6.2

- 执行后生成数据库DB2，数据文件为DataFile2.mdf
- 未指定日志文件，自动生成默认日志文件DB2_log.ldf
- **注意**：指定的目录`D:\datafiles\`必须已经存在，否则创建失败

#### 例6.3 创建同时指定数据文件和日志文件的数据库

```sql
CREATE DATABASE DB3
ON PRIMARY
(
    NAME = 'LogicFile3',
    FILENAME = 'D:\datafiles\DataFile3.mdf'
)
LOG ON
(
    NAME = 'LogicLog3',
    FILENAME = 'D:\datafiles\LogFile3.ldf'
);
```

> 📚 **课本出处**：第6章 6.2.3节 例6.3

> ⚠️ **重要规则**：在CREATE DATABASE语句中，如果要指定日志文件，则**必须指定至少一个数据文件**。LOG ON子句不能单独出现。

---

### 四、创建指定大小的数据库（6.2.4）

> 📚 **课本出处**：第6章 6.2.4节"创建指定大小的数据库"

这里的"大小"包含三个维度：**初始大小**（SIZE）、**最大存储空间**（MAXSIZE）、**自动增长幅度**（FILEGROWTH）。

#### 例6.4 创建指定数据文件大小的数据库

```sql
CREATE DATABASE DB4
ON PRIMARY
(
    NAME = 'LogicFile4',
    FILENAME = 'D:\datafiles\DataFile4.mdf',
    SIZE = 5MB,          -- 设置初始大小
    MAXSIZE = 100MB,     -- 设置数据文件的最大存储空间
    FILEGROWTH = 15MB    -- 设置自动增长幅度
);
```

> 📚 **课本出处**：第6章 6.2.4节 例6.4

#### 例6.5 创建指定数据文件和日志文件大小的数据库

```sql
CREATE DATABASE DB5
ON PRIMARY
(
    NAME = 'LogicFile5',
    FILENAME = 'D:\datafiles\DataFile5.mdf',
    SIZE = 10MB,
    MAXSIZE = 200MB,
    FILEGROWTH = 20MB
)
LOG ON
(
    NAME = 'LogicLog5',
    FILENAME = 'D:\datafiles\LogFile5.ldf',
    SIZE = 10MB,
    MAXSIZE = 100MB,
    FILEGROWTH = 10%     -- 以百分比方式增长
);
```

> 📚 **课本出处**：第6章 6.2.4节 例6.5

> 💡 **理解技巧**：FILEGROWTH支持两种增长方式：
> - **绝对数值**：如20MB，每次增长20MB
> - **百分比**：如10%，每次增长当前大小的10%（10MB -> 11MB -> 12.1MB -> ...）

#### 例6.6 创建带两个数据文件的数据库（主数据文件+次要数据文件）

```sql
CREATE DATABASE DB6
ON PRIMARY
(
    NAME = 'LogicFile6_1',
    FILENAME = 'D:\datafiles\DataFile6.mdf'   -- 主数据文件
),
(
    NAME = 'LogicFile6_2',
    FILENAME = 'D:\datafiles\DataFile6.ndf'   -- 次要数据文件
);
```

> 📚 **课本出处**：第6章 6.2.5节 例6.6

> ⚠️ **常见误区**：主数据文件和次要数据文件不是根据**扩展名**来确定的，而是根据**定义顺序**来确定。紧跟关键字ON PRIMARY之后定义的数据文件为主数据文件，其余的为次要数据文件。

#### 例6.7 创建带用户定义文件组的数据库

```sql
CREATE DATABASE DB7
ON PRIMARY
(
    NAME = 'LogicFile7_1',
    FILENAME = 'D:\datafiles\DataFile7_1.mdf',
    SIZE = 5MB,
    MAXSIZE = 100MB,
    FILEGROWTH = 15%
),
FILEGROUP UserFG7_2
(
    NAME = 'LogicFile7_2',
    FILENAME = 'D:\datafiles\DataFile7_2.ndf',
    SIZE = 2MB,
    MAXSIZE = 100MB,
    FILEGROWTH = 10%
),
FILEGROUP UserFG7_3
(
    NAME = 'LogicFile7_3',
    FILENAME = 'D:\datafiles\DataFile7_3.ndf',
    SIZE = 3MB,
    MAXSIZE = 100MB,
    FILEGROWTH = 5%
)
LOG ON
(
    NAME = 'LogicLog7',
    FILENAME = 'D:\datafiles\LogFile7.ldf',
    SIZE = 10MB,
    MAXSIZE = 100MB,
    FILEGROWTH = 1MB
);
```

> 📚 **课本出处**：第6章 6.2.6节 例6.7

> 💡 **理解技巧**：文件组语法格式为 `FILEGROUP 文件组名`，后面跟该文件组包含的数据文件列表。主数据文件永远自动被划分到主文件组(PRIMARY)中。

## 总结

### CREATE DATABASE参数速查表

| 参数 | 作用 | 数据文件默认值 | 日志文件默认值 | 备注 |
|:----:|:-----|:--------------:|:--------------:|:-----|
| database_name | 数据库名称 | - | - | 实例中唯一，最大128字节 |
| ON PRIMARY | 指定主文件 | 自动生成主文件 | - | 未指定时database_name成为主文件 |
| NAME | 逻辑文件名 | database_name | database_name_log | 面向应用程序 |
| FILENAME | 物理文件名 | 逻辑名.mdf | 逻辑名_log.ldf | 面向操作系统 |
| SIZE | 初始大小 | 3MB | 1MB | 可指定KB/MB/GB/TB |
| MAXSIZE | 最大值 | UNLIMITED | UNLIMITED | 数据文件16TB，日志文件2TB |
| FILEGROWTH | 增长幅度 | - | - | 数值或百分比，0=关闭 |
| LOG ON | 指定日志文件 | - | 数据文件总和的25%或512KB | 必须在有数据文件后才能指定 |
| FILEGROUP | 定义文件组 | - | - | 最多32767个 |
| COLLATE | 排序规则 | 实例默认 | 实例默认 | Windows或SQL排序规则 |

### CREATE DATABASE的简化程度排序

| 复杂度 | 示例 | 说明 |
|:------:|:-----|:-----|
| 最简 | `CREATE DATABASE DB1;` | 仅数据库名，其余全部默认 |
| 指定文件名 | ON PRIMARY (NAME, FILENAME) | 指定逻辑名和物理名 |
| 指定文件名+日志 | ON PRIMARY + LOG ON | 同时指定数据文件和日志文件 |
| 指定大小 | + SIZE, MAXSIZE, FILEGROWTH | 控制文件大小和增长策略 |
| 多文件+文件组 | 多个filespec + FILEGROUP | 完整的文件组组织 |

### 关键要点

1. 除database_name外，所有参数都是**可选**的
2. 主数据文件和次要数据文件由**定义顺序**决定，而非扩展名
3. 指定日志文件时**必须同时指定至少一个数据文件**
4. FILEGROWTH设为0表示**关闭自动增长**功能
5. LOG ON不指定时，日志文件大小自动设置为数据文件总和的**25%或512KB（取大值）**
6. 指定的目录必须**已存在**，且目录下不能有同名文件

## 疑问与思考

### ❓ 待解决问题
1. PRIMARY关键字在什么情况下必须显式指定？省略PRIMARY时数据库名会怎样成为主文件名？
2. SIZE参数设置过小会有什么影响？实际项目中如何合理估算初始大小？
3. FILEGROWTH使用百分比增长和绝对数值增长各有什么优缺点？什么场景下该用哪种？
4. UNLIMITED真的无限增长吗？实际中如何预防数据库文件占满磁盘？

### 💡 个人理解/技巧
- NAME和FILENAME的区别：NAME是给SQL语句用的"别名"，FILENAME是操作系统中实际的文件路径。类比编程中的"变量名"和"内存地址"
- 文件初始大小的设置建议：根据预估数据量，不要设太小（频繁自动增长影响性能），也不要设太大（浪费磁盘空间）
- 自动增长策略建议：
  - 绝对数值增长适合数据量可预估的场景（如每月固定增长20MB）
  - 百分比增长适合数据量不确定的场景，但要注意后期增长量会越来越大（百分比的基数在变）
- 主文件与次要文件的顺序判定：记住"**紧跟PRIMARY之后的是主文件**"，扩展名只是约定，不是判断依据
- 文件组的使用场景：当数据库很大且有多个磁盘时，可以将不同的文件组放在不同磁盘上，提高I/O并行度
