## 重点内容

### ⭐⭐⭐ 核心语法
- **更改数据库名称**：`ALTER DATABASE ... MODIFY NAME = ...` 或 `sp_renamedb`
- **修改数据库大小**：`ALTER DATABASE ... MODIFY FILE`
- **修改数据库的基本方法**：SSMS图形界面 或 `ALTER DATABASE` 语句

### ⭐⭐ 关键注意事项
- 修改数据库文件时，新的初始大小（SIZE）必须**大于**更改前的初始值
- `MODIFY FILE` 中的 `NAME` 参数必须是**原来的逻辑文件名**
- 更改数据库大小实质上是修改数据文件和日志文件的属性

### ⭐ 替代方案比较
- 删除并重建数据库：需备份数据 + 重新设置配置，烦琐且易出错
- 使用 `ALTER DATABASE`：直接修改，无需删除重建，推荐使用

## 详细笔记

### 一、修改数据库概述

> 📚 **课本出处**：第6章 6.4节"修改数据库"

数据库创建后，可能由于当初考虑欠妥或后来需求变化，需要对数据库进行修改。

**两种修改数据库的方法**：

| 方法 | 说明 |
|:-----|:-----|
| SSMS图形界面 | 右击数据库 -> 属性 -> 在"数据库属性"对话框中修改 |
| ALTER DATABASE语句 | 使用SQL语句直接修改，适合编写脚本 |

> ⚠️ **常见误区**：不要采用"先删除再重建"的方式来修改数据库，这种方法需要备份数据并重新设置网络、权限等配置信息，非常烦琐且容易出错。

---

### 二、更改数据库的名称（6.4.1）

> 📚 **课本出处**：第6章 6.4.1节"更改数据库的名称"

#### 方法一：ALTER DATABASE ... MODIFY NAME

```sql
ALTER DATABASE database_name
MODIFY NAME = new_database_name;
```

**【例6.9】更改数据库名**

将已存在的数据库 `oldDB` 改名为 `newDB`：

```sql
ALTER DATABASE oldDB  -- 改名
MODIFY NAME = newDB;
```

#### 方法二：sp_renamedb 存储过程

```txt
sp_renamedb database_name, new_database_name
```

同样的改名操作，也可以用如下语句实现：

```sql
sp_renamedb oldDB, newDB;
```

> 💡 **理解技巧**：两种方法效果完全相同。`ALTER DATABASE ... MODIFY NAME` 是标准SQL语法，`sp_renamedb` 是SQL Server专用存储过程。考试中两种写法都应掌握。

---

### 三、修改数据库的大小（6.4.2）

> 📚 **课本出处**：第6章 6.4.2节"修改数据库的大小"

数据库的大小由**数据文件和日志文件的大小**决定，因此修改数据库大小实质上是修改数据库文件的相关属性值（初始值、增长幅度、最大容量等），使用带 `MODIFY FILE` 选项的 `ALTER DATABASE` 语句来完成。

#### 语法结构

```sql
ALTER DATABASE database_name
MODIFY FILE
(
    NAME = 原逻辑文件名,
    -- 其他需要修改的属性
);
```

**【例6.10】修改数据库的容量，同时修改主数据文件的逻辑名称和物理名称**

将数据库 `testdb` 的数据文件进行如下修改：
- 逻辑名称改为 `newtestdb`
- 物理名称改为 `newtestdb.mdf`
- 初始大小为 25MB
- 最大空间为 150MB
- 增长幅度为 10MB

```sql
USE master
GO
ALTER DATABASE testdb
MODIFY FILE
(
    NAME = testdb,              -- 必须是原来的逻辑文件名
    NEWNAME = newtestdb,        -- 新的逻辑文件名
    FILENAME = 'D:\datafiles\newtestdb.mdf',
                                -- 新的物理文件名（不需要原来的物理文件名）
    SIZE = 25MB,                -- 初始大小
    MAXSIZE = 150MB,            -- 最大存储空间
    FILEGROWTH = 10MB           -- 数据增长幅度
);
```

> ⚠️ **重要注意**：`NAME` 参数必须填写**原来的逻辑文件名**，而不是新的。这是初学者最容易犯的错误。

**【例6.11】更改数据库的日志文件**

更改数据库 `DB3` 的日志文件，将日志文件名变为 `newlogdb3.ldf`（逻辑文件名不变），初始大小为 10MB：

```sql
USE master
GO
ALTER DATABASE DB3
MODIFY FILE
(
    NAME = LogicLog3,                      -- 必须是原来的逻辑文件名
    FILENAME = 'D:\datafiles\newlogdb3.ldf', -- 新的物理文件名
    SIZE = 10MB,                            -- 初始大小
    MAXSIZE = 50MB,                         -- 最大存储空间
    FILEGROWTH = 5MB                        -- 自动增长幅度
);
```

> ⚠️ **关键限制**：对数据文件和日志文件来说，更改后的初始值（SIZE）**必须大于**更改前的初始值，否则 `ALTER` 语句操作将失败。数据库文件只能扩大，不能通过此方法缩小。

## 总结

### 修改数据库语法汇总

| 操作 | 语法 |
|:-----|:-----|
| 更改数据库名（标准SQL） | `ALTER DATABASE old_name MODIFY NAME = new_name;` |
| 更改数据库名（存储过程） | `sp_renamedb old_name, new_name;` |
| 修改数据文件属性 | `ALTER DATABASE db_name MODIFY FILE (NAME=原逻辑名, NEWNAME=新逻辑名, FILENAME='新物理路径', SIZE=大小, MAXSIZE=最大, FILEGROWTH=增长);` |
| 修改日志文件属性 | `ALTER DATABASE db_name MODIFY FILE (NAME=原逻辑名, FILENAME='新物理路径', SIZE=大小, MAXSIZE=最大, FILEGROWTH=增长);` |

### 关键要点

1. 修改数据库有两种方式：SSMS图形界面和 `ALTER DATABASE` 语句
2. 更改数据库名最简单，可用 `MODIFY NAME` 或 `sp_renamedb`
3. 修改数据库大小通过 `MODIFY FILE` 修改文件属性
4. `NAME` 参数必须是**原来的**逻辑文件名
5. 新的 `SIZE` 必须**大于**原来的 `SIZE`，只能扩大不能缩小
6. 更改文件属性时会同时影响物理文件，需确保新路径有效

## 疑问与思考

### ❓ 待解决问题
1. 如果需要缩小数据库文件的大小，应该用什么方法？（提示：`DBCC SHRINKFILE`）
2. `ALTER DATABASE` 还支持哪些 `MODIFY` 选项？如修改数据库的恢复模型、兼容级别等
3. 更改数据库名称后，依赖该数据库名的应用程序连接字符串是否需要同步修改？

### 💡 个人理解/技巧
- 修改数据库名只是修改"标签"，不会影响数据库内部的数据文件和日志文件
- 修改数据库大小实际上是在修改文件的元数据（大小、增长策略），而不是直接操作磁盘
- `SIZE` 不能缩小是出于安全考虑——防止误操作导致数据截断
- 例6.10中同时修改了逻辑名和物理名，实际操作中这两个可以分开修改
- 修改操作完成后，建议使用 `sp_helpdb` 验证修改是否生效
