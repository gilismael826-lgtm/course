## 重点内容

### ⭐⭐⭐ 核心概念

1. **FTP**：使用TCP可靠传输，客户/服务器方式，两个并行连接（控制+数据）
2. **控制连接**（端口21）：整个会话保持打开，传送命令和响应
3. **数据连接**（端口20）：实际传输文件，传输完关闭
4. **带外传送**：控制信息通过独立的控制连接传送
5. **TFTP**：使用UDP，简单，512字节数据块，停止等待协议，端口69
6. **NFS**：联机访问，不复制整个文件，操作系统提供透明访问

### ⭐⭐ 关键问题

- FTP为什么使用两个TCP连接？
- FTP与TFTP的主要区别是什么？
- 带内传送和带外传送的含义？
- TFTP的停止等待机制如何保证可靠传输？

## 详细笔记

### 一、FTP概述

**FTP (File Transfer Protocol)** 曾是互联网上使用最广泛的文件传送协议。

**特点**：
- 提供交互式访问，可指明文件类型和格式
- 允许文件具有存取权限（需授权和口令）
- 屏蔽各计算机系统的细节，适合异构网络
- 使用 **TCP** 可靠的运输服务

> 互联网早期，FTP通信量占整个互联网的1/3，1995年WWW才超过FTP。

**文件共享协议两大类**：

| 类型 | 代表 | 特点 |
|------|------|------|
| **复制整个文件** | FTP、TFTP | 必须先获得本地副本，修改后再传回 |
| **联机访问** | NFS | 允许多个程序同时存取，操作系统提供透明访问 |

***

### 二、FTP的基本工作原理

**FTP使用客户/服务器方式**，服务器进程由两部分组成：
- **主进程**：负责接受新的请求（端口21）
- **从属进程**：负责处理单个请求，处理完即终止

**两个并行的TCP连接**：

| 连接 | 端口 | 作用 | 生命周期 |
|------|------|------|----------|
| **控制连接** | 21 | 传送命令和响应 | 整个会话期间保持打开 |
| **数据连接** | 20 | 实际传输文件 | 传输完毕后关闭 |

> FTP的控制信息是**带外(out of band)**传送的。

**使用两个连接的好处**：
1. 协议更简单，更容易实现
2. 传输文件时可利用控制连接进行控制（如终止传输）

**主进程工作步骤**：
1. 打开熟知端口（21），等待客户连接
2. 收到请求后启动从属进程处理
3. 从属进程处理完毕后终止
4. 主进程回到等待状态，继续接受其他请求

***

### 三、简单文件传送协议TFTP

**TFTP (Trivial File Transfer Protocol)** 是一个很小且易于实现的文件传送协议。

**特点**：
- 使用 **UDP** 数据报（需自己的差错改正措施）
- 不支持交互，没有列目录功能，不能身份鉴别
- 每次传送 **512字节** 数据，最后一次可不足512字节
- 数据报文按序编号，从1开始
- 支持ASCII码或二进制传送
- 使用很简单的首部

**工作方式**：类似**停止等待协议**
- 发送完一个文件块后等待确认
- 超时未收到确认则重发
- 熟知端口号为 **69**

**TFTP优点**：
1. 可用于UDP环境（如同时向多台机器下载）
2. 代码占内存小（对小型设备很重要）

**文件结束标志**：
- 文件长度恰好为512字节整数倍：最后发送一个只含首部无数据的数据报文
- 文件长度不是512字节整数倍：最后数据报文不满512字节

## 疑问与思考

### ❓ 待解决问题

#### 1. FTP为什么使用两个TCP连接？

**📚 课本出处**：第6章 6.2.2节

FTP使用控制连接和数据连接两个独立的TCP连接，主要好处：

1. **协议更简单、更容易实现**：控制信息和数据分离，各自独立处理
2. **传输控制更灵活**：传输文件时可通过控制连接发送控制命令（如请求终止传输），而不会影响数据传输
3. **避免混乱**：使用不同端口号（21和20），数据连接与控制连接不会混淆

这种带外传送控制信息的方式，使FTP在文件传输过程中仍能响应用户的控制命令。

#### 2. FTP与TFTP的主要区别是什么？

**📚 课本出处**：第6章 6.2.2节、6.2.3节

| 对比项 | FTP | TFTP |
|--------|-----|------|
| 传输协议 | TCP | UDP |
| 可靠性 | 由TCP保证 | 自己实现停止等待机制 |
| 交互性 | 支持交互 | 不支持交互 |
| 身份鉴别 | 支持 | 不支持 |
| 列目录 | 支持 | 不支持 |
| 数据块大小 | 不固定 | 512字节 |
| 端口 | 21（控制）、20（数据） | 69 |
| 复杂度 | 较复杂 | 简单，代码小 |
| 适用场景 | 一般文件传输 | 小型设备、批量下载 |

#### 3. 什么是带内传送和带外传送？

**📚 课本出处**：第6章 6.2.2节

| 传送方式 | 含义 | 示例 |
|----------|------|------|
| **带内传送** | 控制信息和数据在同一条连接上传送 | HTTP |
| **带外传送** | 控制信息通过独立的连接传送 | FTP（控制连接单独建立） |

FTP使用带外传送的好处是：即使文件传输正在进行，用户也可以通过控制连接发送控制命令（如中断传输），而不会影响数据连接。

### 💡 个人理解

- FTP的双连接设计虽然增加了复杂性，但带来了更好的灵活性和可控性。现代文件传输工具很多都借鉴了这种思想。
- TFTP的简单性使其在嵌入式系统和网络设备引导时非常有用（如无盘工作站、路由器固件更新），因为不需要复杂的TCP协议栈。
- NFS的联机访问方式比FTP更高效，特别是只需要修改文件一小部分内容时，不需要传输整个文件。

## 核心考点总结

### ⭐⭐⭐ 必考内容

1. **FTP核心特点**

| 项目 | 内容 |
|------|------|
| 协议 | TCP |
| 架构 | 客户/服务器 |
| 控制连接端口 | 21（整个会话保持打开） |
| 数据连接端口 | 20（传输完关闭） |
| 控制信息传送 | 带外(out of band) |

2. **FTP工作过程**

```mermaid
flowchart LR
    A[FTP客户] -->|控制连接:21| B[FTP服务器主进程]
    B --> C[从属进程]
    A -->|数据连接:20| C
```

3. **FTP vs TFTP对比**

| 对比项 | FTP | TFTP |
|--------|-----|------|
| 传输协议 | TCP | UDP |
| 端口 | 21/20 | 69 |
| 交互性 | 有 | 无 |
| 身份鉴别 | 有 | 无 |
| 数据块 | 不固定 | 512字节 |
| 可靠性 | TCP保证 | 停止等待机制 |

4. **TFTP工作方式**
- 类似停止等待协议
- 每次512字节，编号从1开始
- 超时重发
- 最后不足512字节表示文件结束

### 📌 易混淆点辨析

| 概念 | 说明 |
|------|------|
| **带内传送** | 控制信息和数据在同一条连接上传输（如HTTP） |
| **带外传送** | 控制信息通过独立连接传输（如FTP的控制连接） |
| **主进程** | FTP服务器中负责接受新请求的进程 |
| **从属进程** | FTP服务器中处理单个请求的进程，处理完即终止 |
| **NFS** | 联机访问，不复制整个文件，操作系统透明访问 |
| **TFTP** | 简单文件传送，UDP，512字节块，停止等待 |
