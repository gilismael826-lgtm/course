## 重点内容

### ⭐⭐ 核心概念

1. **专用地址（私有地址）**：RFC1918规定的三段地址，仅用于内部通信
2. **VPN**：利用公用互联网作为通信载体，通过隧道技术实现专用网效果
3. **NAT**：网络地址转换，将本地地址转换为全球IP地址
4. **NAPT**：网络地址与端口号转换，多个主机共享一个全球IP地址

### ⭐⭐ 关键问题

- 专用地址的范围有哪些？
- VPN为什么称为"虚拟"？
- NAT和NAPT的区别？
- 为什么专用网内主机不能直接充当服务器？

## 详细笔记

### 一、虚拟专用网VPN

#### 1. 专用地址（Private Address）

**问题背景**：

- 机构内部使用本地地址
- 若与互联网IP地址重合，会出现**地址二义性**

**RFC1918规定的专用地址**：

| 地址块                | 范围                             | 相当于      |
| ------------------ | ------------------------------ | -------- |
| **10.0.0.0/8**     | 10.0.0.0 \~ 10.255.255.255     | 1个A类网络   |
| **172.16.0.0/12**  | 172.16.0.0 \~ 172.31.255.255   | 16个B类网络  |
| **192.168.0.0/16** | 192.168.0.0 \~ 192.168.255.255 | 256个C类网络 |

**专用地址特点**：

- 只能用于**机构内部通信**
- **不能**用于和互联网主机通信
- 互联网路由器对目的地址是专用地址的数据报**一律不转发**
- 也叫**可重用地址**（reusable address）

**专用网**：采用专用IP地址的互连网络

- 全世界可能有多个专用网使用相同IP地址
- 不会引起麻烦，因为仅在机构内部使用

#### 2. VPN的概念

**应用场景**：

- 大型机构的部门分布在世界各地
- 需要经常交换信息

**两种实现方法**：

| 方法       | 说明            | 缺点   |
| -------- | ------------- | ---- |
| **租用专线** | 租用电信公司通信线路    | 租金太高 |
| **VPN**  | 利用公用互联网作为通信载体 | 成本低  |

**VPN（Virtual Private Network）**：

- **虚拟**：没有真正使用通信专线，效果上和真正的专用网一样
- **专用网**：为本机构主机用于机构内部通信

**VPN特点**：

- 通信必须经过公用的互联网
- 需要**加密**保证数据安全
- 需要专门硬件和软件配置

#### 3. VPN的类型

| 类型                    | 说明            |
| --------------------- | ------------- |
| **内联网（Intranet VPN）** | 场所A和B都属于同一个机构 |
| **外联网（Extranet VPN）** | 有外部机构（合作伙伴）参加 |
| **远程接入VPN**           | 流动员工通过拨号接入    |

**注意**：内联网和外联网都基于TCP/IP协议。

#### 4. VPN的工作原理（隧道技术）

![图4-64 VPN隧道技术](../../../images/7cf23a6fb5294998347e990e8a011bcdb7ebab2d93f0b15f4bb8c5ab56497cff.jpg)

![图4-64 VPN构成](../../../images/5a5ee9883790dcf438bd8395fa882264bbfb9c4c35fc1bf866955609cc43a32d.jpg)

> 📚 **课本出处**：图4-64 使用IP隧道技术实现VPN，内部数据报加密后封装在外部数据报中

**示例场景**：

- 场所A网络地址：10.1.0.0
- 场所B网络地址：10.2.0.0
- 路由器R1全球地址：125.1.2.3 
- 路由器R2全球地址：194.4.5.6

**通信过程**：

```mermaid
sequenceDiagram
    participant X as 主机X<br>10.1.0.1
    participant R1 as 路由器R1<br>125.1.2.3
    participant Internet as 互联网
    participant R2 as 路由器R2<br>194.4.5.6
    participant Y as 主机Y<br>10.2.0.3
    
    X->>R1: 内部数据报<br>源:10.1.0.1 目的:10.2.0.3
    Note over R1: 加密内部数据报<br>添加外部首部
    R1->>Internet: 外部数据报<br>源:125.1.2.3 目的:194.4.5.6
    Internet->>R2: 外部数据报
    Note over R2: 解密<br>恢复内部数据报
    R2->>Y: 内部数据报<br>源:10.1.0.1 目的:10.2.0.3
```

**隧道概念**：

- 数据报从R1到R2可能经过很多网络和路由器
- 逻辑上看，R1到R2好像是一条直通的点对点链路
- 这条逻辑链路就是"**隧道**"

### 二、网络地址转换NAT

#### 1. NAT概述

**应用场景**：

- 专用网内部主机已分配本地IP地址
- 想与互联网上的主机通信
- 不需要加密

**NAT（Network Address Translation）**：

- 1994年提出
- 在专用网连接互联网的路由器上安装NAT软件
- 装有NAT软件的路由器称为**NAT路由器**

**NAT路由器要求**：

- 至少有一个有效的**外部全球IP地址**

#### 2. NAT工作原理

#### 📷 图4-65 NAT路由器的工作原理

![图4-65 NAT工作原理](../../../images/9c6537f76b6fd4e32869c22189d84e577789d50b46af6985867097ff99048615.jpg)

> 📚 **课本出处**：图4-65 NAT通过转换表将本地地址转换为全球IP地址

**示例**：

- 专用网：192.168.0.0
- 主机A本地地址：192.168.0.3
- NAT路由器全球地址：172.38.1.5
- 互联网主机B地址：213.18.2.4

**通信过程**：

| 步骤 | 方向    | 数据报 | 源地址         | 目的地址        |
| -- | ----- | --- | ----------- | ----------- |
| ①  | A→B   | 内部  | 192.168.0.3 | 213.18.2.4  |
| ②  | NAT转发 | 外部  | 172.38.1.5  | 213.18.2.4  |
| ③  | B→A   | 应答  | 213.18.2.4  | 172.38.1.5  |
| ④  | NAT转发 | 内部  | 213.18.2.4  | 192.168.0.3 |

**NAT转换表**：

| 方向 | 本地地址        | 全球地址        |
| -- | ----------- | ----------- |
| 出  | 192.168.0.3 | 172.38.1.5  |
| 入  | 172.38.1.5  | 192.168.0.3 |

**NAT特点**：

- 主机B不知道A的专用地址（192.168.0.3）
- 即使知道也不能使用（互联网路由器不转发专用地址）
- NAT路由器有n个全球IP地址，最多n台主机同时接入互联网

#### 3. NAT的局限性

**必须由专用网内主机发起通信**：

- 若外部主机发起通信，NAT路由器不知道转换为哪个本地IP地址
- 专用网内部主机**不能直接充当服务器**

#### 4. NAPT（网络地址与端口号转换）

**问题**：如何使更多主机共享有限的全球IP地址？

**解决方案**：使用**端口号**区分不同主机

#### 📊 表4-9 NAPT地址转换表举例

| 方向 | 字段           | 原先的IP地址和端口号       | 转换后的IP地址和端口号      |
| -- | ------------ | ----------------- | ----------------- |
| 出  | 源IP:TCP源端口   | 192.168.0.3:30000 | 172.38.1.5:40001  |
| 出  | 源IP:TCP源端口   | 192.168.0.4:30000 | 172.38.1.5:40002  |
| 入  | 目的IP:TCP目的端口 | 172.38.1.5:40001  | 192.168.0.3:30000 |
| 入  | 目的IP:TCP目的端口 | 172.38.1.5:40002  | 192.168.0.4:30000 |

**NAPT特点**：

- 多个主机**共享一个全球IP地址**
- 通过不同**端口号**区分不同主机
- 可同时和互联网上不同主机通信

**端口号说明**：

- 端口号仅在本主机中有意义
- 不同主机可以选择相同端口号（巧合）
- NAPT转换为不同的新端口号

**NAT vs NAPT**：

| 类型        | 全称                                   | 转换内容     | 特点           |
| --------- | ------------------------------------ | -------- | ------------ |
| **传统NAT** | Network Address Translation          | 仅IP地址    | 一个全球IP对应一台主机 |
| **NAPT**  | Network Address and Port Translation | IP地址+端口号 | 多个主机共享一个全球IP |

#### 5. NAT/NAPT的层次问题

**普通路由器**：

- 转发IP数据报时，源/目的IP地址**不改变**
- 工作在**网络层**

**NAT路由器**：

- 转发IP数据报时，**更换IP地址**
- 工作在**网络层**

**NAPT路由器**：

- 还要查看和转换**运输层端口号**
- 跨越网络层和运输层

**争议**：

- NAPT操作没有严格按照层次关系
- 但NAT/NAPT已成为互联网重要构件

## 疑问与思考

### ❓ 待解决问题

#### 1. 内联网VPN和外联网VPN的区别是什么？

**📚 课本出处**：第4章 4.8.1节

内联网VPN（Intranet VPN）和外联网VPN（Extranet VPN）的核心区别在于参与方的范围：

| 对比项 | 内联网VPN | 外联网VPN |
|--------|-----------|-----------|
| **参与方** | 同一机构的多个场所 | 本机构 + 合作伙伴 |
| **信任关系** | 内部信任 | 需要额外的访问控制 |
| **安全要求** | 机构内部策略 | 需对外部机构限制权限 |
| **典型场景** | 总部与分支机构互连 | 与供应商、客户共享部分资源 |

外联网VPN是在内联网基础上扩展而来的，关键在于对合作伙伴的访问范围进行精细控制，只允许访问特定的网络资源。

#### 2. NAT耗尽问题是什么？如何解决？

**📚 课本出处**：第4章 4.8.2节

**NAT耗尽问题**：当NAT路由器只有一个全球IP地址时，该路由器最多只能让**一台主机**同时接入互联网。即使使用NAPT，端口号只有16位（0~65535），理论上一台NAT路由器最多支持约6万台主机同时通信，但实际上很多端口号被系统占用，实际并发数远低于此。

**解决方法**：

| 方案 | 说明 |
|------|------|
| **多分配全球IP地址** | NAT路由器拥有多个全球IP，每增加一个IP增加一台主机 |
| **使用NAPT** | 通过端口号区分，多台主机共享一个全球IP |
| **运营商级NAT（CGN）** | 在运营商侧再做一次NAT，级联使用 |
| **过渡到IPv6** | 从根源上解决地址不足问题，每台设备可拥有全球唯一地址 |

#### 3. 三段专用地址的范围和各自适用场景？

**📚 课本出处**：第4章 4.8.1节，RFC1918

| 地址块 | 范围 | 容量 | 适用场景 |
|--------|------|------|----------|
| **10.0.0.0/8** | 10.0.0.0 ~ 10.255.255.255 | 约1677万台 | 大型企业/机构，地址空间充足 |
| **172.16.0.0/12** | 172.16.0.0 ~ 172.31.255.255 | 约104万台 | 中型企业 |
| **192.168.0.0/16** | 192.168.0.0 ~ 192.168.255.255 | 约6.5万台 | 小型网络/家庭网络，最常用 |

**注意**：这三段地址在全球范围内是可重用的，不同机构可以重复使用相同的专用地址，因为它们不会出现在互联网上。

#### 4. 为什么NAT路由器只能由内向外发起通信？

**📚 课本出处**：第4章 4.8.2节

当外部主机试图主动向专用网内的主机发送数据时，NAT路由器收到该数据报后，查找NAT转换表，但表中**没有对应的转换记录**（因为之前没有内部主机向该外部主机发起过通信），因此无法确定应该将数据报转发给哪台内部主机。

这就导致了：**专用网内部的主机不能直接充当服务器**，因为服务器需要被动接受外部的连接请求。

### 💡 个人理解

- VPN的核心思想是"封装+加密"，把内部数据报整个包裹在外部数据报中传输，就像把一封私密信件装在一个普通信封里寄出去，外人看到的只是普通信封的地址。
- NAT本质上是一种"地址翻译"机制，它解决了IPv4地址不足的燃眉之急，但它的存在实际上破坏了IP地址的端到端原则——这在IPv6中将不再需要。
- NAPT能成为互联网上最广泛部署的技术之一，说明了工程实践中"不完美但实用"的方案往往比"完美但复杂"的方案更有生命力。
- VPN和NAT虽然解决不同问题，但都是IPv4时代的关键补丁技术，随着IPv6的普及，它们的重要性会逐渐降低。

## 总结

### VPN与NAT对比

| 特性 | VPN | NAT/NAPT |
|------|-----|----------|
| **目的** | 跨公网安全通信 | 解决IPv4地址不足 |
| **工作原理** | 隧道封装+加密 | 地址/端口转换 |
| **地址使用** | 专用地址之间互通 | 专用地址转为全球地址 |
| **安全性** | 高（加密传输） | 低（不提供加密） |
| **典型场景** | 远程办公、分支机构互连 | 家庭/企业上网 |

### 专用地址范围

| 地址块 | CIDR | 范围 | 网络数 |
|--------|------|------|--------|
| 10.0.0.0/8 | A类 | 10.0.0.0 ~ 10.255.255.255 | 1个A类网络 |
| 172.16.0.0/12 | B类范围 | 172.16.0.0 ~ 172.31.255.255 | 16个B类网络 |
| 192.168.0.0/16 | C类范围 | 192.168.0.0 ~ 192.168.255.255 | 256个C类网络 |

### NAT类型

| 类型 | 转换内容 | 共享方式 | 特点 |
|------|----------|----------|------|
| **传统NAT** | 仅IP地址 | 一对一 | 一个全球IP对应一台主机 |
| **NAPT** | IP+端口号 | 多对一 | 多台主机共享一个全球IP，最常用 |

### 核心概念脑图

```
VPN和NAT
├── VPN（虚拟专用网）
│   ├── 隧道技术：内部报文加密封装在外部报文中
│   ├── 内联网VPN：同一机构不同场所
│   ├── 外联网VPN：包含合作伙伴
│   └── 远程接入VPN：员工远程拨号
├── NAT（网络地址转换）
│   ├── 基本NAT：一对一IP转换
│   ├── NAPT：多对一，IP+端口转换
│   └── 局限性：必须由内向外发起，不能充当服务器
└── 专用地址（RFC1918）
    ├── 10.0.0.0/8（1个A类）
    ├── 172.16.0.0/12（16个B类）
    └── 192.168.0.0/16（256个C类）
```
