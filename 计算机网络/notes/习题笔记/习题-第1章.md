### 1-02 试简述分组交换的要点。

#### 💡 解答

分组交换的要点如下：

1. **采用存储转发技术**：在发送端，先把较长的报文划分成较短的、固定长度的数据段，每个数据段前面加上首部构成分组（ packet ）。

2. **首部包含控制信息**：每个分组的首部都含有地址等控制信息，路由器根据首部中的地址信息将分组转发到下一站。

3. **逐段占用通信资源**：分组交换以分组作为传输单元，采用存储转发方式，逐段地占用通信资源，不需要预先建立连接，通信线路不为某一对通信双方所独占。

4. **高效、灵活、迅速、可靠**：
   - **高效**：在分组传输过程中动态分配传输带宽，对通信链路是逐段占用的
   - **灵活**：为每个分组独立选择最合适的转发路由
   - **迅速**：以分组为单位传送，不用先建立连接就能向其他主机发送分组
   - **可靠**：保证可靠性的网络协议，分布式多路由的分组交换网使网络有很好的生存性

### 1-05 互联网基础结构的发展大致分为哪几个阶段？请指出这几个阶段最主要的特点。

#### 💡 解答

| 阶段 | 时间 | 主要特点 |
|:----:|:-----|:---------|
| **第一阶段** | 1969-1990 | 从单个网络ARPANET向互连网发展。1983年TCP/IP协议成为ARPANET标准协议，是互联网的诞生时间 |
| **第二阶段** | 1985-1993 | 建成三级结构的互联网：主干网、地区网、校园网（企业网）。NSFNET成为互联网主要组成部分 |
| **第三阶段** | 1993至今 | 逐渐形成全球范围的多层次ISP结构的互联网。出现互联网服务提供者ISP，互联网交换点IXP使数据流量分布更合理 |

### 1-12 互联网的两大组成部分（边缘部分与核心部分）的特点是什么？

#### 💡 解答

| | 边缘部分 | 核心部分 |
|:--|:---------|:---------|
| **组成** | 所有连接在互联网上的主机（端系统） | 大量网络和连接这些网络的路由器 |
| **功能** | 用户直接使用，进行通信和资源共享 | 为边缘部分提供连通性和交换服务 |
| **工作方式** | 客户-服务器方式（C/S）或对等方式（P2P） | 路由器转发分组（分组交换） |
| **特点** | 主机直接为用户提供服务 | 路由器不直接为用户提供服务 |

### 1-13 客户-服务器方式与P2P对等通信方式的主要区别是什么？有没有相同的地方？

#### 💡 解答

**主要区别**：

| | 客户-服务器方式 | P2P方式 |
|:--|:----------------|:--------|
| **服务关系** | 客户是服务请求方，服务器是服务提供方 | 不区分服务请求方和服务提供方 |
| **地位** | 客户和服务器地位不平等 | 双方对等，平等通信 |
| **运行方式** | 服务器长期运行，被动等待；客户主动请求 | 每台主机既是客户又是服务器 |

**相同的地方**：
- 本质上P2P仍然使用客户-服务器方式，只是每台主机既是客户同时又是服务器
- 都需要使用网络核心部分提供的服务
- 通信都可以是双向的

### 1-14 计算机网络有哪些常用的性能指标？

#### 💡 解答

| 性能指标 | 定义 | 单位 |
|:---------|:-----|:-----|
| **速率** | 数据的传送速率（数据率/比特率） | bit/s（bps）|
| **带宽** | 网络中某通道传送数据的能力 | Hz 或 bit/s |
| **吞吐量** | 单位时间内通过某个网络的实际数据量 | bit/s 或 B/s |
| **时延** | 数据从网络的一端传送到另一端所需的时间 | s |
| **时延带宽积** | 传播时延 x 带宽 | bit |
| **往返时间RTT** | 从发送方发送数据到收到接收方确认的总时间 | s |
| **利用率** | 信道有百分之几的时间是被利用的 | % |

**时延的组成**：发送时延 + 传播时延 + 处理时延 + 排队时延

### 1-17 收发两端之间的传输距离为1000km，信号在媒体上的传播速率为 2×10⁸ m/s。试计算以下两种情况的发送时延和传播时延。

#### 💡 解答

**已知条件**：
- 距离：1000 km = 10⁶ m
- 传播速率：2×10⁸ m/s
- **传播时延** = 距离 / 传播速率 = 10⁶ / (2×10⁸) = **5 ms**

**(1) 数据长度为10⁷ bit，数据发送速率为100 kbit/s**

| 时延类型 | 计算 | 结果 |
|:---------|:-----|:-----|
| 发送时延 | 10⁷ / (100×10³) | **100 s** |
| 传播时延 | 10⁶ / (2×10⁸) | **5 ms** |

**(2) 数据长度为10³ bit，数据发送速率为1 Gbit/s**

| 时延类型 | 计算 | 结果 |
|:---------|:-----|:-----|
| 发送时延 | 10³ / 10⁹ | **1 μs** |
| 传播时延 | 10⁶ / (2×10⁸) | **5 ms** |

**结论**：
- 若数据长度大而发送速率低，则**发送时延**往往大于传播时延
- 若数据长度短而发送速率高，则**传播时延**可能是总时延的主要成分

### 1-18 假设信号在媒体上的传播速率为 2.3×10⁸ m/s。计算不同媒体长度和数据率下在媒体中的比特数。

#### 💡 解答

媒体中的比特数 = 传播时延 × 数据率 = (媒体长度 / 传播速率) × 数据率

| 媒体长度 | 传播时延 | 数据率=1Mbit/s | 数据率=10Gbit/s |
|:---------|:---------|:--------------:|:---------------:|
| 0.1 m (网络接口卡) | 4.35×10⁻¹⁰ s | 4.35×10⁻⁴ bit | 4.35 bit |
| 100 m (局域网) | 4.35×10⁻⁷ s | 0.435 bit | 4.35×10³ bit |
| 100 km (城域网) | 4.35×10⁻⁴ s | 4.35×10² bit | 4.35×10⁶ bit |
| 5000 km (广域网) | 0.0217 s | 2.17×10⁴ bit | 2.17×10⁸ bit |

### 1-19 长度为100字节的应用层数据交给运输层传送，需加上20字节的TCP首部。再交给网络层传送，需加上20字节的IP首部。最后交给数据链路层的以太网传送，加上首部和尾部共18字节。试求数据的传输效率。

#### 💡 解答

**(1) 应用层数据长度为100字节时**

| 层次 | 开销 | 数据 |
|:-----|:-----|:-----|
| 应用层数据 | - | 100 B |
| TCP首部 | 20 B | - |
| IP首部 | 20 B | - |
| 以太网首部和尾部 | 18 B | - |
| **总发送数据** | **58 B** | **100 B** |

总数据 = 100 + 20 + 20 + 18 = 158 字节

传输效率 = 100 / 158 = **63.3%**

**(2) 应用层数据长度为1000字节时**

总数据 = 1000 + 20 + 20 + 18 = 1058 字节

传输效率 = 1000 / 1058 = **94.5%**

**结论**：数据长度越大，首部和尾部所占比例越小，传输效率越高。

### 1-21 协议与服务有何区别？有何关系？

#### 💡 解答

**区别**：

| | 协议 | 服务 |
|:--|:-----|:-----|
| **定义** | 控制两个对等实体进行通信的规则集合 | 下层为上层提供的功能 |
| **可见性** | 协议对上层透明，上层看不到 | 服务对上层可见 |
| **关系** | 对等实体之间 | 上下层之间 |
| **方向** | 水平的（对等层）| 垂直的（上下层）|

**关系**：
- 在协议的控制下，两个对等实体间的通信使得本层能够向上一层提供服务
- 要实现本层协议，还需要使用下层所提供的服务
- 协议是"水平的"，服务是"垂直的"
- 协议是控制对等实体之间通信的规则，服务的实现依赖于协议

### 1-22 网络协议的三个要素是什么？各有什么含义？

#### 💡 解答

| 要素 | 含义 | 说明 |
|:-----|:-----|:-----|
| **语法** | 数据与控制信息的结构或格式 | 规定通信双方"如何讲"，如报文中各字段的排列顺序和格式 |
| **语义** | 需要发出何种控制信息，完成何种动作以及做出何种响应 | 规定通信双方"讲什么"，如各个字段的含义和取值 |
| **同步** | 事件实现顺序的详细说明 | 规定通信双方"何时讲"，如通信的状态变化和各状态的转换条件 |

### 1-24 试述具有五层协议的网络体系结构的要点，包括各层的主要功能。

#### 💡 解答

| 层次 | 名称 | 主要功能 | 数据单元 |
|:----:|:-----|:---------|:---------|
| 5 | **应用层** | 通过应用进程间的交互完成特定网络应用（HTTP、DNS、SMTP等）| 报文(message) |
| 4 | **运输层** | 向两台主机中进程之间的通信提供通用的数据传输服务（TCP、UDP）| 报文段/用户数据报 |
| 3 | **网络层** | 为分组交换网上的不同主机提供通信服务，选择路由转发分组（IP）| 分组/数据报 |
| 2 | **数据链路层** | 将IP数据报组装成帧，在相邻节点间传送帧，进行差错检测 | 帧(frame) |
| 1 | **物理层** | 透明地传送比特流，规定电压、接口、引脚等电气特性 | 比特(bit) |

**要点**：
- 各层之间独立，上层通过接口使用下层服务
- 对等层之间通过协议进行通信
- 数据传递过程中，发送端逐层封装，接收端逐层解封

### 1-26 试解释以下名词：协议栈、实体、对等层、协议数据单元、服务访问点、客户、服务器、客户-服务器方式。

#### 💡 解答

| 名词 | 解释 |
|:-----|:-----|
| **协议栈** | 计算机网络各层及其协议的集合，因各层画在一起像栈的结构而得名 |
| **实体** | 任何可发送或接收信息的硬件或软件进程 |
| **对等层** | 不同机器上位于同一层次、完成相同功能的层 |
| **协议数据单元PDU** | OSI参考模型中，对等层次之间传送的数据单位 |
| **服务访问点SAP** | 相邻两层之间交互信息的地方，即层与层之间的接口 |
| **客户** | 通信中请求服务的一方，主动发起通信 |
| **服务器** | 通信中提供服务的一方，被动等待请求 |
| **客户-服务器方式** | 通信中一方为客户（请求服务），另一方为服务器（提供服务）的工作方式 |

### 1-29 有一个点对点链路，长度为50km。若数据在此链路上的传播速率为 2×10⁸ m/s，试问链路的带宽应为多少才能使传播时延和发送100字节的分组的发送时延一样大？

#### 💡 解答

**已知条件**：
- 链路长度：50 km = 5×10⁴ m
- 传播速率：2×10⁸ m/s
- 分组长度：100 字节 = 800 bit

**计算传播时延**：
$$传播时延 = 距离 / 传播速率 = 5×10⁴ / (2×10⁸) = 2.5×10⁻⁴ s = 0.25 ms$$

**计算带宽**（发送时延 = 传播时延）：
$$带宽 = 数据长度 / 发送时延 = 800 / (2.5×10⁻⁴) = 3.2×10⁶ bit/s = 3.2 Mbit/s$$

**发送512字节分组时**：
- 数据长度 = 512×8 = 4096 bit
- 带宽 = 4096 / (2.5×10⁻⁴) = 16.384×10⁶ bit/s = **16.38 Mbit/s**

### 1-30 有一个点对点链路，长度为20000km。数据的发送速率是1kbit/s，要发送的数据有100 bit。数据在此链路上的传播速率为 2×10⁸ m/s。假定我们可以看见在线路上传输的比特，试画出我们看到的线路上的比特。

#### 💡 解答

**已知条件**：
- 链路长度：20000 km = 2×10⁷ m
- 发送速率：1 kbit/s
- 数据量：100 bit
- 传播速率：2×10⁸ m/s

**计算**：
- 发送时延 = 100 / 1000 = 0.1 s
- 传播时延 = 2×10⁷ / (2×10⁸) = 0.1 s
- 每比特宽度（距离）= 发送速率 / 传播速率 = 1000 / (2×10⁸) = 5×10⁻⁶ m = **5 mm**
- 100 bit在链路上占据的距离 = 100 × 5 mm = **0.5 m**

**图1：100 bit刚刚发送完时**
- 发送端刚发完第100个比特
- 第1个比特已传播了0.1 s，恰好到达链路的中间（10000 km处）
- 线路上有100个比特，从发送端开始延伸到链路中间

```
发送端 |100个比特(总长0.5m)|          空          | 接收端
       |←——— 0.5m ———→|←——— 约20000km ———→|
```

**图2：再经过0.05s后**
- 此时总时间 = 0.1 + 0.05 = 0.15 s
- 第1个比特又传播了 0.05 × 2×10⁸ = 10000 km，到达接收端
- 第100个比特传播了 10000 km，到达链路中间
- 100个比特仍然分布在链路上，位置向接收端移动了

### 1-31 条件同上题，但数据的发送速率改为1 Mbit/s。和上题的结果相比较，你可以得出什么结论？

#### 💡 解答

**已知条件**：
- 发送速率：1 Mbit/s = 10⁶ bit/s
- 其他条件同1-30

**计算**：
- 发送时延 = 100 / 10⁶ = 10⁻⁴ s = 0.1 ms
- 传播时延 = 0.1 s（不变）
- 每比特宽度（距离）= 10⁶ / (2×10⁸) = 5×10⁻³ m = **5 m**
- 100 bit在链路上占据的距离 = 100 × 5 m = **500 m**

**图1：100 bit刚刚发送完时**
- 发送端刚发完第100个比特（仅用0.1 ms）
- 第1个比特只传播了 0.1 ms，距离 = 0.1×10⁻³ × 2×10⁸ = 20 km
- 100个比特紧紧挤在发送端附近，仅占据500m

**图2：再经过0.05s后**
- 第1个比特传播了 0.0501 s，距离 = 10020 km
- 100个比特仍然紧紧挤在一起，向接收端移动

**结论**：
- 发送速率提高时，每比特在链路上占据的距离变大（从5mm变为5m）
- 高速发送时，比特在链路上分布更"稀疏"（占据距离更长）
- 低速发送时，比特紧紧挤在一起；高速发送时，比特分布更分散
- 当发送速率极高时，链路上同时存在的比特数更多
