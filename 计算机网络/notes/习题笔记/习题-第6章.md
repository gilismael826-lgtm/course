### 6-02 域名系统的主要功能是什么？各类域名服务器有何区别？

#### 💡 解答

**域名系统的主要功能**：将便于人们记忆的域名解析转换为计算机能识别的IP地址，为互联网的各种网络应用提供核心名字服务。

**各类域名服务器的区别**：

| 类型 | 作用 | 特点 |
|:-----|:-----|:-----|
| **根域名服务器** | 最高层次，知道所有顶级域名服务器的域名和IP地址 | 不直接解析所有域名，但知道下一步该找哪个顶级域名服务器 |
| **顶级域名服务器** | 管理在该顶级域名下注册的所有二级域名 | 如.com、.cn等顶级域的服务器 |
| **权限域名服务器** | 负责一个区的域名解析，保存该区所有主机的域名到IP地址的映射 | 每个主机必须在某个权限域名服务器处注册登记 |
| **本地域名服务器** | 当主机发出DNS查询请求时，首先发给本地域名服务器 | 距离用户最近，起代理作用，常使用高速缓存 |

### 6-05 FTP的主要工作过程是怎样的？为什么说FTP是带外传送控制信息？主进程和从属进程各起什么作用？

#### 💡 解答

**FTP的主要工作过程**：
FTP使用客户-服务器方式，服务器进程由两大部分组成：一个主进程和若干个从属进程。

**主进程的工作步骤**：
1. 打开熟知端口（端口号21），使客户进程能够连接上
2. 等待客户进程发出连接请求
3. 启动从属进程处理客户进程发来的请求
4. 回到等待状态，继续接受其他客户进程发来的请求

**为什么说FTP是带外传送控制信息**：
FTP使用两个并行的TCP连接：控制连接（端口21）和数据连接（端口20）。控制连接在整个会话期间一直保持打开，用来传送控制命令；而实际用于传输文件的是数据连接。由于控制信息通过独立的控制连接传送，而不是通过数据连接，因此FTP的控制信息是**带外(out of band)**传送的。

**主进程的作用**：负责接受新的请求，打开熟知端口，等待客户连接，并启动从属进程。

**从属进程的作用**：负责处理单个请求，包括控制进程和数据传送进程，处理完毕后即终止。

### 6-08 解释以下名词

#### 💡 解答

| 名词 | 英文原文 | 解释 |
|:-----|:---------|:-----|
| **WWW** | World Wide Web | 万维网，是一个大规模的、联机式的信息储藏所，用链接的方法从互联网上的一个站点访问另一个站点 |
| **URL** | Uniform Resource Locator | 统一资源定位符，用来标志万维网上的各种文档，使每个文档在互联网范围内有唯一的标识符 |
| **HTTP** | HyperText Transfer Protocol | 超文本传送协议，定义浏览器如何向万维网服务器请求文档，以及服务器如何将文档传送给浏览器 |
| **HTML** | HyperText Markup Language | 超文本标记语言，用于设计万维网页面的语言，可使用链接从本页面链接到互联网上任何页面 |
| **CGI** | Common Gateway Interface | 通用网关接口，定义动态文档如何创建，以及输入数据如何传给应用程序的输出 |
| **浏览器** | Browser | 在用户主机上的万维网客户程序，用来显示万维网页面并与用户交互 |
| **超文本** | Hypertext | 包含指向其他文档链接的文本，由多个信息源链接而成 |
| **超媒体** | Hypermedia | 超文本系统的扩充，文档中不仅包含文本，还包含图形、图像、声音、动画、视频等 |
| **超链** | Hyperlink | 超文本中的链接，点击可从一个文档链接到另一个文档 |
| **页面** | Page | 在浏览器主窗口上显示出的万维网文档 |
| **活动文档** | Active Document | 由服务器发送过来的程序在客户端创建，是一种提供屏幕连续更新的技术 |
| **搜索引擎** | Search Engine | 在万维网中用来进行搜索信息的工具，分为全文检索和分类目录搜索 |

### 6-10 从已知URL获得一个万维网文档，除HTTP外，还需要什么应用层协议和运输层协议？

#### 💡 解答

**应用层协议**：**DNS（域名系统）**
- 原因：题目已知"该万维网服务器的IP地址开始时并不知道"，需要通过DNS将URL中的主机名解析为IP地址

**运输层协议**：**TCP**
- 原因：HTTP使用TCP连接进行可靠的报文传输；DNS查询通常使用UDP，但也可使用TCP

**总结**：除HTTP外，还需要 **DNS**（应用层）和 **TCP**（运输层，HTTP基于TCP；DNS查询通常基于UDP）。

### 6-14 判断以下论述的正误，并简述理由

#### 💡 解答

**(1) 用户点击某网页，该网页有1个文本文件和3个图片。此用户可以发送一个请求就可以收到4个响应报文。**
> **错误**。HTTP/1.0中每个请求/响应对都需要独立的TCP连接（非持续连接），需要发送4个请求；HTTP/1.1持续连接可以复用TCP连接，但仍需发送4个请求，收到4个响应。

**(2) 有以下两个不同的网页：www.abc.com/m1.html 和 www.abc.com/m2.html。用户可以使用同一个HTTP/1.1持续连接传送对这两个网页的请求和响应。**
> **正确**。HTTP/1.1的持续连接可以在同一个TCP连接上传送同一服务器上的多个请求和响应，这两个网页在同一服务器上，可以复用同一个持续连接。

**(3) 在客户与服务器之间的非持续连接，只需要用一个TCP报文段就能够装入两个不同的HTTP请求报文。**
> **错误**。非持续连接对每个请求都要建立新的TCP连接，每个HTTP请求报文都需要独立的TCP连接，不能将两个不同请求装入同一个TCP报文段。

**(4) 在HTTP响应报文中的主体实体部分永远不会是空的。**
> **错误**。HTTP响应报文中的实体主体部分可以为空，例如：状态码204（No Content）表示请求成功但无返回内容；或者某些HEAD请求的响应。

### 6-15 DNS解析时间计算

#### 💡 解答

**题目**：经过n个DNS服务器，时间分别为RTT₁, RTT₂, ..., RTTₙ，到网页的往返时间是RTT_w，求从点击URL到屏幕出现小图片的总时间。

**解答**：

DNS查询采用递归查询方式：
- 从本地主机到本地域名服务器：RTT₁
- 本地域名服务器进行迭代查询，依次访问根、顶级、权限域名服务器，每次查询往返时间为RTT₂, ..., RTTₙ

总共需要经过 **2RTT_w + ΣRTTᵢ (i=1到n)** 的时间。

**详细分析**：
- DNS解析时间：RTT₁ + RTT₂ + ... + RTTₙ（共n个RTT）
- 建立TCP连接：RTT_w
- 请求和接收文档：RTT_w

**总计**：**ΣRTTᵢ (i=1→n) + 2RTT_w**

### 6-16 计算客户点击读取对象所需的时间

#### 💡 解答

**题目条件**：HTML文件链接了3个非常小的对象，忽略发送时间。

**(1) 没有并行TCP连接的非持续HTTP**
- 每个对象都需要建立新的TCP连接并请求
- 每个对象需要 2RTT_w（建立TCP连接 + 请求/响应）
- 共4个对象（1个HTML + 3个小对象）
- **总时间 = 4 × 2RTT_w = 8RTT_w**

**(2) 使用并行TCP连接的非持续HTTP**
- 浏览器通常打开5~10个并行TCP连接
- 4个对象可以并行下载
- 建立连接和请求可以并行
- **总时间 = 2RTT_w（HTML）+ 2RTT_w（3个对象并行）= 4RTT_w**

**(3) 流水线方式的持续HTTP**
- TCP连接建立后，所有请求和响应都在一个连接上
- 建立TCP连接：RTT_w
- 请求HTML并响应：RTT_w
- 请求3个对象（流水线方式，只需一个RTT_w）：RTT_w
- **总时间 = 3RTT_w**

### 6-20 电子邮件最主要的组成部件。用户代理UA的作用是什么？没有UA行不行？

#### 💡 解答

**电子邮件系统最主要的组成部件**：
1. **用户代理UA**（User Agent）
2. **邮件服务器**
3. **邮件发送协议和邮件读取协议**（如SMTP、POP3、IMAP）

**用户代理UA的作用**：
1. **撰写**：给用户提供编辑信件的环境
2. **显示**：在计算机屏幕上方便地显示来信
3. **处理**：发送邮件和接收邮件，对来信进行管理（删除、存盘、打印、转发等）
4. **通信**：发件人利用邮件发送协议将邮件发送到邮件服务器；收件人使用邮件读取协议从邮件服务器接收邮件

**没有UA行不行**？
> **不行**。没有UA，用户无法方便地撰写、编辑、显示和管理邮件。虽然理论上可以直接使用SMTP/POP3命令与邮件服务器交互，但这要求用户熟悉协议命令，对用户极不友好，且无法提供友好的图形界面和邮件管理功能。

### 6-23 简述SMTP通信的三个阶段的过程

#### 💡 解答

SMTP通信分为三个阶段：

**1. 连接建立**
- 发件人的邮件送到发送方邮件服务器的邮件缓存后，SMTP客户就使用熟知端口25与接收方邮件服务器的SMTP服务器建立TCP连接
- 接收方SMTP服务器发出"220 Service ready"
- SMTP客户发送HELO命令（或EHLO），附上发送方的主机名
- SMTP服务器若有能力接收邮件，则回答"250 OK"

**2. 邮件传送**
- 从MAIL命令开始，后面有发件人地址
- 跟着一个或多个RCPT命令（收件人地址）
- 再下面就是DATA命令，表示开始传送邮件内容
- 服务器返回"354 Start mail input; end with <CRLF>.<CRLF>"
- 客户发送邮件内容，发送完毕后发送<CRLF>.<CRLF>表示邮件内容结束
- 服务器返回"250 OK"

**3. 连接释放**
- 邮件发送完毕后，SMTP客户发送QUIT命令
- SMTP服务器返回"221（服务关闭）"，表示同意释放TCP连接
- 邮件传送的全部过程即结束

### 6-31 基于万维网的电子邮件系统有什么特点？在传送邮件时使用什么协议？

#### 💡 解答

**基于万维网的电子邮件系统的特点**：
1. **使用浏览器收发邮件**：用户不需要安装专门的用户代理程序，只需使用浏览器即可收发电子邮件
2. **界面统一**：收发邮件的界面与浏览万维网的界面相同，操作方便
3. **邮件保存在服务器**：用户邮件保存在邮件服务器中，可在任何地方通过浏览器访问
4. **功能丰富**：可方便地进行邮件管理、搜索、分类等操作

**传送邮件时使用的协议**：
- **发送邮件**：使用 **SMTP** 协议
- **读取邮件**：使用 **HTTP** 协议（而非POP3/IMAP，因为通过浏览器访问邮件服务器时，邮件服务器与浏览器之间使用HTTP传送邮件信息）

> 注意：基于万维网的电子邮件与普通电子邮件的区别在于**读取邮件时**使用HTTP协议代替POP3/IMAP，但**发送邮件时**仍然使用SMTP协议。
